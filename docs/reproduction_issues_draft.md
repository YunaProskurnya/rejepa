# Замечания к воспроизведению I-JEPA (черновик)

Этот список фиксирует расхождения, обнаруженные при чтении статей, авторского кода и README проекта. Он не означает, что влияние каждого расхождения на качество уже измерено.

## 1. Функция ошибки I-JEPA: формула и код

В [статье I-JEPA, §3](https://arxiv.org/html/2301.08243#S3) ошибка предсказания записана через **квадрат L2-нормы** разности представлений патчей. В [официальном `train.py`](https://github.com/facebookresearch/ijepa/blob/main/src/train.py) используется `F.smooth_l1_loss`. Наш [код](../src/losses.py) в `main` также считает Smooth L1 (`beta=1`, `reduction="mean"`); MSE добавлен как отдельный режим в экспериментальной ветке `authoreg`. Поэтому «воспроизвести формулу статьи» и «повторить опубликованную реализацию» здесь означают разные настройки. Кроме формы ошибки, явная сумма по патчам в статье и усреднение в коде дают разные масштабы loss.

## 2. VISReg: формулы, псевдокод и наша реализация

В [статье VISReg, §3.1](https://arxiv.org/html/2606.02572#S3.SS1) и [псевдокоде авторов](https://haiyuwu.github.io/visreg/) не полностью совпадают нормировки. Детали и принятые нами решения уже записаны в [README регуляризаторов](../src/regularizers/README.md):

| Слагаемое | Формула статьи | Псевдокод / наш код |
| --- | --- | --- |
| `center` | `||mean_batch(z)||²`, сумма квадратов по `D` признакам | `mean(mean_batch(z)²)`, в `D` раз меньше |
| `shape` | Формула (5): среднее по `K` проекциям от **суммы** квадратов по `N` изображениям | Среднее по `K × N`, в `N` раз меньше; при этом лемма 3.2 самой статьи содержит деление на `N` |
| Нормализация для `shape` | В знаменателе есть `stop_gradient(std) + ε` | В псевдокоде `ε` опущен; наш код использует `ε`, как в формуле |

Эти множители меняют относительный вес `center` и `shape` при фиксированных коэффициентах. Поэтому перед сопоставлением результатов нужно указать, какая версия формул взята и какие фактические веса использованы.

## 3. VISReg в этом проекте — адаптация метода

VISReg задаёт полную цель как `(1−λ)·prediction + λ·regularization`, а здесь используется `prediction + regularizer_weight·regularization` ([README](../README.md#режимы-обучения-и-регуляризация)). Для одинакового **отношения** весов нужен `regularizer_weight = λ/(1−λ)`; общий масштаб градиента при этом остаётся другим. Регуляризация у нас также применяется отдельно к каждой позиции патча и усредняется по позициям, тогда как VISReg рассматривает эмбеддинги изображений. Следовательно, запуск `--regularizer visreg` нельзя выдавать за точное повторение экспериментального протокола VISReg.

## 4. Масштаб эксперимента и оценка

В статье I-JEPA результаты для ViT-B/16 получены на ImageNet-1K при 600 эпохах, с типичным batch size 2048; [наш базовый конфиг](../configs/imagenet100_vit_base.json) рассчитан на ImageNet100, 10 эпох и batch size 128 с отдельно выбранным масштабированием learning rate. Это проверка реализации и устойчивости обучения, а не прямое воспроизведение опубликованной точности. Наш kNN анализ также не равен linear probe из статьи. Для сравнения качества нужны одинаковое разбиение данных, одинаковые checkpoint и протокол оценки; один лишь низкий training loss не подтверждает отсутствие коллапса.
